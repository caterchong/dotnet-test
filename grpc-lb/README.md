# gRPC 客户端负载均衡测试

本项目用于测试 .NET 环境下 `Grpc.Net.Client` 在客户端负载均衡方面的表现。

## 项目结构

- **Shared**: 共享的 proto 文件定义和生成的客户端代码
- **GrpcServer**: gRPC 服务端，支持配置端口
- **GrpcClient**: gRPC 客户端，实现负载均衡和健康检查
- **TestRunner**: 自动化测试运行器，测试各种负载均衡场景

## 功能特性

1. **多服务器实例支持**: 启动多个 gRPC 服务实例（默认端口 50051, 50052, 50053）
2. **客户端负载均衡**: 使用 Round-Robin 算法在多个服务器间分配请求
3. **健康检查**: 定期检查服务器健康状态，自动移除不健康的实例
4. **DNS Resolver 支持**: 支持使用 DNS resolver 进行服务发现
5. **故障检测**: 自动检测服务器故障并摘除异常实例
6. **动态服务发现**: 支持动态添加和移除服务器实例

## 构建项目

```bash
# 构建所有项目
dotnet build

# 构建 Release 版本
dotnet build -c Release
```

## 运行方式

### 方式1: 手动启动服务器和客户端

#### 1. 启动3个服务器实例

```bash
# 终端1
cd GrpcServer
dotnet run 50051

# 终端2
cd GrpcServer
dotnet run 50052

# 终端3
cd GrpcServer
dotnet run 50053
```

#### 2. 启动客户端

```bash
cd GrpcClient
dotnet run "http://localhost:50051,http://localhost:50052,http://localhost:50053" 60 1000
```

参数说明：
- 第一个参数: 服务器地址列表（逗号分隔）
- 第二个参数: 测试持续时间（秒）
- 第三个参数: 请求间隔（毫秒）

### 方式2: 使用测试运行器（推荐）

```bash
cd TestRunner
dotnet run
```

测试运行器会自动：
1. 启动3个服务器实例
2. 运行基本负载均衡测试
3. 测试添加新服务器实例的场景
4. 测试移除服务器实例的场景
5. 测试服务器宕机的场景
6. 测试服务器恢复的场景

## 测试场景

### 场景1: 基本负载均衡
- 启动3个服务器实例
- 客户端连接到所有实例
- 验证请求在服务器间均匀分布

### 场景2: 添加新服务器实例
- 运行过程中添加第4个服务器实例
- 测试客户端需要多久可以感知到新实例
- 验证新实例开始接收请求

### 场景3: 移除服务器实例
- 运行过程中停止一个服务器实例
- 测试客户端需要多久可以感知到实例移除
- 验证请求不再发送到已停止的实例

### 场景4: 服务器宕机
- 模拟服务器突然宕机（kill 进程）
- 测试客户端如何处理：
  - 是否主动摘除异常实例
  - 还是等待 DNS 通知后再摘除
- 验证健康检查机制的有效性

### 场景5: 服务器恢复
- 重启之前宕机的服务器
- 测试客户端是否能够重新发现并恢复使用该实例

## DNS Resolver 使用

### 使用 DNS 地址

```bash
# 客户端使用 DNS resolver
cd GrpcClient
dotnet run "dns://localhost:50051" 60 1000
```

注意：DNS resolver 会定期（每30秒）刷新 DNS 记录，自动发现新的服务实例。

### 配置本地 DNS（可选）

如果需要测试真实的 DNS 解析，可以配置本地 DNS 服务器（如 dnsmasq）或使用 Kubernetes 的 DNS 服务。

3. 创建 Service 暴露服务

## 实现细节

### 负载均衡算法
- 当前实现使用 Round-Robin 算法
- 只将请求发送到健康的服务器实例

### 健康检查
- 每10秒执行一次健康检查
- 使用 gRPC Health Check 协议
- 超时时间：2秒

### DNS 刷新
- DNS resolver 每30秒刷新一次
- 自动发现新添加的服务实例
- 延迟移除不再存在的实例（2分钟）以处理 DNS 延迟

### 故障处理
- 健康检查失败后立即标记为不健康
- 不健康的实例不会接收新请求
- 如果所有实例都不健康，会尝试使用所有实例（包括不健康的）

## 注意事项

1. **端口冲突**: 确保端口 50051-50054 未被占用
2. **防火墙**: 确保防火墙允许这些端口的连接
3. **DNS 缓存**: 某些系统可能有 DNS 缓存，影响 DNS resolver 的测试结果
4. **健康检查频率**: 可以根据需要调整健康检查间隔

## 故障排查

### 客户端无法连接到服务器
- 检查服务器是否正在运行
- 检查端口是否正确
- 检查防火墙设置

### 负载不均衡
- 检查所有服务器是否健康
- 查看客户端日志中的端点状态
- 验证服务器端口是否正确返回

### DNS resolver 不工作
- 检查 DNS 地址是否正确
- 验证 DNS 服务器是否可访问
- 查看 DNS 刷新日志
