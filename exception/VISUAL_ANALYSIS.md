## 性能变化趋势分析

### 随错误频率变化的性能成本

假设每 1000 次操作中，有 X% 发生错误：

```
错误率 0% (10,000 次操作)
├─ 异常方式: 2.917 × 10,000 = 29,170 ns
└─ 返回值方式: 16.514 × 10,000 = 165,140 ns
   性能比: 返回值 慢 5.7 倍

错误率 1% (9,900 次正常 + 100 次错误)
├─ 异常方式: (2.917 × 9,900) + (14,314.3 × 100) = 28,870 + 1,431,430 = 1,460,300 ns
└─ 返回值方式: (16.514 × 9,900) + (7.846 × 100) = 163,389 + 784.6 = 164,174 ns
   性能比: 异常方式 慢 8.9 倍

错误率 10% (9,000 次正常 + 1,000 次错误)
├─ 异常方式: (2.917 × 9,000) + (14,314.3 × 1,000) = 26,253 + 14,314,300 = 14,340,553 ns
└─ 返回值方式: (16.514 × 9,000) + (7.846 × 1,000) = 148,626 + 7,846 = 156,472 ns
   性能比: 异常方式 慢 91.7 倍

错误率 50% (5,000 次正常 + 5,000 次错误)
├─ 异常方式: (2.917 × 5,000) + (14,314.3 × 5,000) = 14,585 + 71,571,500 = 71,586,085 ns
└─ 返回值方式: (16.514 × 5,000) + (7.846 × 5,000) = 82,570 + 39,230 = 121,800 ns
   性能比: 异常方式 慢 587.5 倍

错误率 100% (10,000 次错误)
├─ 异常方式: 14,314.3 × 10,000 = 143,143,000 ns
└─ 返回值方式: 7.846 × 10,000 = 78,460 ns
   性能比: 异常方式 慢 1,823 倍
```

## 关键洞察

### 📌 洞察 1: 正常情况下的权衡
- **异常方式快** 5.7 倍（因为 JIT 优化了异常的正常路径）
- **返回值方式占用内存** 144 B（Result 对象）
- **结论**: 但如果异常发生，所有的性能优势都会消失

### 📌 洞察 2: 错误情况下的灾难
- **异常方式慢 1,823 倍**
- **内存分配多 11 倍**
- **GC 压力高 6 倍**
- **结论**: 即使错误较少，仍然可能导致严重的性能问题

### 📌 洞察 3: 破裂点在哪里？

根据上面的趋势分析：
- 错误率 < 0.01% 时，异常方式仍然优于返回值
- 错误率 > 1% 时，返回值方式明显优于异常
- 错误率 > 10% 时，异常方式性能灾难

### 📌 洞察 4: 实际应用中的真实影响

假设一个服务每秒处理 100,000 个请求，错误率 5%：

```
异常方式:
- 正常请求: 95,000 × 2.917 ns = 277,115,000 ns
- 错误请求: 5,000 × 14,314.3 ns = 71,571,500 ns
- 总时间: 348,686,500 ns = 348.69 ms (额外延迟 / 秒)
- GC 收集次数: 765 次收集

返回值方式:
- 正常请求: 95,000 × 16.514 ns = 1,568,830,000 ns
- 错误请求: 5,000 × 7.846 ns = 39,230 ns
- 总时间: 1,568,869,230 ns = 1,568.87 ms
- GC 收集次数: 250 次收集
```

## 结论和建议

### ✅ 何时使用异常

```
真正异常情况 →
├─ 不可恢复的错误 (例: OutOfMemoryException)
├─ 编程错误 (例: ArgumentNullException)
└─ 罕见的系统错误 (例: I/O 失败)
```

### ❌ 何时不要使用异常

```
予期的业务错误 →
├─ 验证失败
├─ 业务规则不符
├─ 预期的控制流
└─ 任何频繁发生的错误
```

### 🎯 最佳实践代码模式

```csharp
// ❌ 反模式: 异常作为控制流
public class BadExample
{
    public int ParseValue(string input)
    {
        try
        {
            return int.Parse(input);  // 用户输入经常无效
        }
        catch (FormatException)
        {
            return 0;
        }
    }
}

// ✅ 好模式: 使用 TryParse
public class GoodExample
{
    public int ParseValue(string input)
    {
        if (int.TryParse(input, out var result))
            return result;
        return 0;
    }
}
```
